# CLI フレームワークの拡張計画

初回リリースで対象外とした機能のうち、AI エージェントが `--help` を読んで正しく呼び出し、失敗を機械的に修正できる CLI の基盤として必要なものを追加する。元の [cli-framework.md](../cli-framework.md) は初回リリースの仕様として保存する。各フェーズのチェック欄は実装の完了状態を表し、すべて未着手とする。

基準実装は `13111cf`、初回リリースの検証記録は [acceptance.md](../../issues/cli-framework/acceptance.md)。現状の公開 API は `defineCommand`、`runCommand`、`runMain` とエラー型であり、ヘルプは無色、コマンド定義とサブコマンドは静的に解決する。

## 共通方針

- 既存 API の既定動作を維持する。新しい挙動はオプションや追加 API で選択する。
- zod 4 と zod/mini の両対応、`z.output` の型推論、ESM、Node 22.18 以上と Deno の npm 経由利用を維持する。
- 引数の解釈は既存の共通トークン処理に集約する。ヘルプ、ルーティング、検証で別々の走査規則を増やさない。
- 親はサブコマンドより前の引数だけを検証し、子を実行するときに親の `run` は呼ばない。未知オプションの保存順と `--` の境界を維持する。
- citty の構成や実装を参考にできる。ただし、上記の zitty 固有の仕様を優先する。コードを転載する場合はライセンス表示を保持する。
- 各フェーズは仕様・型・実装・テスト・README を揃えて独立にレビューする。公開 API 案はそのフェーズの着手時に確定し、変更理由を実行記録へ残す。
- 公開、リリース作成、外部スクリプトの移行は本計画に含めない。

## 採用未定の候補

本計画の範囲外だが、AI エージェント向けの CLI 基盤として効果が見込めるもの。採用する場合はフェーズ2の後に別フェーズとして追加する。

- コマンド定義を機械可読な形式で出力する。zod 4 の `z.toJSONSchema` を用い、MCP のツール定義などへ変換できるようにする。
- 検証エラーを構造化して取り出せるようにする。対象フィールドと期待値を JSON で得られる形を想定する。

## 完了判定と実行記録

各フェーズで、関連要件の型・挙動テスト、`pnpm ready`、`pnpm test:packed` を実行する。公開型と tarball を確認し、Node の対応下限と Deno で新機能を実際に使うケースを追加する。テストの成功だけでなく、各フェーズの受け入れ条件と対応付けて確認する。

実行時は `docs/issues/cli-framework-next/` に要件対応表と担当を記録する。本書や各フェーズの全文を各 issue や引き継ぎに複製せず、フェーズ・節・変更点を参照する。レビュー開始時の実装コミットを固定し、修正時は同じ担当へ差分と指摘を渡す。

元の未チェック21項目は、フェーズ1〜3と [deferred.md](deferred.md) のどちらかですべて扱う。追加の明示的対象外である構造化オプションも deferred.md に含める。
